`resupply → retreat → support → cover → flank → objective → engage → hunt → search → objective/patrol fallback`

- Selection precedence stays byte-for-byte equivalent in meaning:
  `resupply > retreat > support > cover > flank > map objective > engage > hunt > search > fallback`.
- Resupply remains `pickupTarget && visible && hpPct < .48`.
- Retreat keeps `targetPos && strategicRetreat && ((hpPct < .25 && dist < 20) || (localThreats >= 3 && hpPct < .58))`.
- Cover keeps the existing target/cover predicate and the strict `hpPct < .72` local-threat branch.
- Flank requires target, committed flank point and `tacticalMode==='flank'`.
- `mapOrderWanted` continues to beat engage/hunt/search.
- Engage range remains `weapon.range * 1.14` for ally and `* 1.08` otherwise.

- A state-selection execution consumes exactly one RNG draw for `stateCD=.22+random*.30`; no extra branch-specific draws are introduced.
- When `stateCD>0`, the orchestrator must not invoke selection and therefore must consume zero selection RNG.
- Existing state execution and side-effect order after selection remain unchanged.
